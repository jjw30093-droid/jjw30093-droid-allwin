## 1. 假设

**H1(单侧)**:在 Crown 亚洲让球主盘口于 T-24h 到收盘(kickoff−10min)之间发生变动的比赛中,
按收盘线、Crown 收盘水位押线移动的反方向,其命中率高于保本胜率。
**H0**:命中率 ≤ 保本胜率。

来源:主研究 Phase 4 的 M2(`margin ~ closing_line + M2`,coef −0.166/档,q=0.051)与 M2
诊断中未预注册的反向下注描述(25/26,N=567,ROI +4.06%,bootstrap 95% CI [−3.34, +11.23],
命中 55.6% vs 保本 53.1%)。M2 未通过主研究的水位感知检验(证据不足,未证实),因此本假设
只能用**尚未发生的比赛**重新检验,25/26 与此前 26/27 的任何数字都不计入。

## 2. 下注规则(冻结)

| 项 | 定义 |
|---|---|
| 市场/公司 | NowGoal `bronze_ng_odds_snap`,`market='ah'`,`company_id='3'`(Crown);只有一条主盘口,不做选线 |
| 水位过滤 | `home+away ∉ [1.60, 2.10]` 或单边 `<0.30` 的 snap 不参与取点(同 PREREG §6.3) |
| T-24h 线 | `observed_at ≤ kickoff−24h` 的最后一条;首条 snap 晚于 kickoff−24h → 无 T-24h → **不下注**(记 `no_t24`) |
| 收盘线 | `observed_at ≤ kickoff−10min` 的最后一条;距 kickoff >120 分钟 → **不下注**(记 `no_close`) |
| 触发 | `Δline = closing_line − line_T24 ≠ 0`(库内符号:`line>0` = 主让;Δline>0 = 线向主队方向移动);`Δline = 0` → 不下注(记 `no_move`) |
| 方向 | `Δline > 0` → 押**客**;`Δline < 0` → 押**主** |
| 价格 | 收盘线 + 收盘 snap 的该方向 Crown 水位(港式赔率 w),平注 1 单位 |
| 结算 | `settle_home(home−away, closing_line)`(与 `reco_settlement_math` 已逐场核对);押客取负;盈亏 = `s·w`(s>0)或 `s`(s≤0),赢半/输半按 ±0.5,走水 0 |
| 每场 | 至多 1 注;比赛只计 `status='Finish'`、`kickoff_precision='exact'`、xref `auto_ok/confirmed` |

Δline 的幅度不加权、不设门槛、不按联赛/半季筛选(这些在 25/26 描述里都看过,不得进规则)。

## 4. 评估(冻结)

- **触发点**:累计下注数(实际记录到的、有结算结果的注)达到 **1600** 时做且仅做一次检验。
  期间只记录计数,不计算、不查看命中率/ROI(记录脚本不输出这两个数;评估脚本在 N<1600 时
  拒绝运行,无覆盖开关)。
- **主检验**:单侧,α=0.05。
  - 命中 = 盈亏 >0(含赢半);失手 = 盈亏 <0(含输半);走水(=0)剔除,不计入分母。
  - 保本胜率 `p0` = 剔除走水后各注 `1/(1+w_i)` 的平均(w_i 为该注实际收盘水位)。
  - 统计量:精确二项检验,`n` = 命中+失手,`x` = 命中,H1: p > p0;p 值 = P(X ≥ x | n, p0)。
    p ≤ 0.05 → "H-M2 在前瞻样本中获得支持(α=0.05,单侧)";否则 → "未获支持"。只有这两种结论。
- **次要报告**(不参与判定):ROI 及 bootstrap 95% CI(2000 次,seed 20260928)、按联赛/按方向
  (押主/押客)拆分的 N 与命中率、Δline 幅度分布、缺失原因计数(`no_t24`/`no_close`/`no_move`)。
- **功效(事先算清)**:p0≈0.531(25/26 描述中反方向平均水位 0.882),N=1600 决胜注,单侧
  α=0.05、80% 功效可检出的命中率 ≈ p0 + 2.49·√(p0(1−p0)/1600) ≈ **0.562**(+3.1 个百分点);
  若真实命中率如 25/26 描述的 55.6%(+2.5 个百分点),功效约 64%。
- **到达 1600 注的预期时间**:25/26 五大联赛 1608 场中 Δline≠0 的比例 35.3%(567 场)→ 每个
  完整赛季约 1752×0.353 ≈ 620 注;26/27 第 N 轮起剩余约 1550 场 ≈ 545 注;**累计 1600 注预计
  要到 2028/29 赛季中段**。这是站长设定的阈值带来的后果,如实写明;若改阈值必须在实施前改本文件。

- 代码:`research/ah_signals/hm2_log.py`(记录)与 `research/ah_signals/hm2_evaluate.py`(评估),

- 记录目录:`/home/ubuntu/research_out/ah_signals/hm2/`(仓库外,不进 git):
  - `hm2_bets.csv`:每场一行(含不下注的场次及原因),字段:`logged_at, match_id, league_id,
    round, kickoff_at_utc, home, away, t24_at, line_t24, t24_home_w, t24_away_w, close_at,
    closing_line, close_home_w, close_away_w, dline, side, water_used, home_score, away_score,
    settle, payoff, reason`;

  完赛后回看与开球前实时读取得到同一条"最后一条",因此赛后补记与前瞻记录等价(26/27 是 5 分钟
  实时轮询,收盘 snap 结构性 ≥10 分钟,与规则一致)。
- 运行方式(待站长选择):
  (a)人工每周执行一次 `nice -n 19 python3 research/ah_signals/hm2_log.py`;或
  (b)ubuntu 用户级 crontab(不需要 sudo、不动 systemd)每天 05:00 UTC 跑一次。
  记录脚本的 stdout 只打印:本次新增场次、累计场次、累计下注数、缺失原因计数;**不打印命中率/ROI**。
- 评估脚本:`hm2_evaluate.py` 读取 `hm2_bets.csv`,若下注数 <1600 直接退出并打印当前计数;
  ≥1600 时只对**前 1600 注**(按 kickoff 排序)做 §4 检验,输出原始 stdout,同时把结果追加进本文件
  修订记录。评估只允许运行一次(在 `hm2_state.json` 记 `evaluated_at`,再次运行拒绝)。

## 6. 风险与如实声明

- 采集中断(`allwin-odds.timer` 故障、NowGoal 域名变更等)会造成整场缺 T-24h/收盘 snap →
  记 `no_t24`/`no_close`,不补、不估;缺失比例在评估时一并报告。
- Crown 水位的港式格式已核验(docs/data-sources.md §2.8);若来源格式变化,水位过滤会把 snap
  整体过滤掉,表现为大量 `no_close`,评估时必须先查这一点。
- 本假设来自事后观察(25/26 描述性 ROI),先验弱;前瞻检验的意义正是把它和"看过的数据"隔开。
- 记录脚本不产生任何下注行为,只是纸面记录(paper log)。
