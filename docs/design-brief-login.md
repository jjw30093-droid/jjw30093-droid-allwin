## 3. 环境判定(登录流程本身不能变,只改视觉)

真实登录方式是**带参二维码 + 微信服务器 webhook 回调**,不是网页授权跳转
(网页授权域名要求 ICP 备案,本站海外部署没有备案)。三种环境走同一套
接口,只是提示文案不同(客户端用 `navigator.userAgent` 判断,判断结果
在 SSR 阶段是 `null`,水合后才知道,所以有个短暂的骨架态):

| 环境 | 标题 | 操作提示 |
|---|---|---|
| 桌面浏览器 | 微信扫码登录 | 用手机微信「扫一扫」,在微信内确认后自动登录 |
| 微信内置浏览器 | 微信内登录 | 长按二维码,选择「识别图中二维码」,确认后自动登录 |
| 非微信手机浏览器 | 微信扫码登录(手机) | 截图保存二维码,在微信「扫一扫 → 相册」中识别,确认后自动登录 |

这三条文案是**真实操作路径**,不是随便写的提示语——手机上不能对着自己
屏幕的二维码扫自己,所以手机端是"截图 + 相册识别"这条路,不能简化成
和桌面端一样的"扫一扫"。

## 4. 真实状态机(`ScanLoginCard` 内部,`DeviceState`)

真实创建请求的响应样本(`POST /api/v1/auth/wechat/device`,开发环境
Mock Provider):

```json
{
  "request_id": "8e017a28-bdfa-4388-a119-7d6340b62327",
  "secret": "dQjaj-lTqJeou2-gSDIGD8h4Txe_FWJKgY6nb15tSHw",
  "qr_url": "https://example.invalid/mock-wechat-qr/8e017a28-bdfa-4388-a119-7d6340b62327",
  "expires_at": "2026-08-13T11:18:39Z"
}
```

`secret` **只留在浏览器内存**,绝不出现在二维码或 URL 里(红线,见 §5);
`qr_url` 才是二维码的真实内容,开发环境是占位域名,生产环境是真实微信
带参二维码链接。

六个状态,一个页面区域(`.qrBox`)里切换,不是弹窗:

1. **idle / creating**——"正在生成扫码请求…"(进卡片即自动发起,无需
   用户点按钮)
2. **waiting**(核心态)——真二维码(200×200,白底黑码,深色模式下也要
   保持白底,否则码块对比度不够扫不出来)+ 环境对应的操作提示 + 倒计时
   "N 秒后过期"(**真实倒计时**,来自 `expires_at`,不是营销倒计时)+
   一句"扫码后如提示关注公众号,关注即完成登录…"。开发环境额外有一个
   折叠的"模拟扫码"调试面板(展示 request_id + 复制按钮 + CLI 命令提示)
   ——**这块必须保持折叠/开发环境限定**,不能在生产设计稿里当成常驻内容。
3. **claimed**——"登录成功,正在跳转…"(短暂态,几乎来不及细看,不用
   过度设计)
4. **expired**——"扫码请求已过期" + "重新生成"按钮
5. **error**——具体错误文案(如"无法创建扫码登录请求,请确认后端服务
   已启动后重试") + "重试"按钮

## 5. 硬性规则

1. **二维码必须是真实可扫的码**,不是装饰性图案或占位符——当前实现用
   `qrcode` 库把 `qr_url` 渲染成真实 canvas 二维码,深浅色模式下都要保持
   白底黑码(码本身的对比度不能被深色主题吞掉)。
2. **倒计时是真实的**(来自后端 `expires_at`,不是前端瞎写的秒数),这点
   和比赛详情页的开球倒计时同一条纪律(CLAUDE.md §11.2 不伪造紧迫感)——
   但这里的倒计时不是"营销紧迫感",是真实的请求有效期,过期后必须真的
   进入"已过期"态,不能继续假装能扫。
3. **secret 绝不进二维码**——二维码内容只是公开的 `request_id`,浏览器
   `secret` 只存在内存里,轮询 claim 时才带上。设计稿不需要关心这条
   (纯前端实现细节),但如果重画二维码周边的信息展示,不要"为了好看"
   把 secret 或 request_id 印到二维码可见区域旁边太显眼的位置——当前
   `request_id` 只在开发环境的折叠调试面板里出现。
4. **开发环境调试面板保持折叠 + 明确标注"开发环境"**——生产环境根本不会
   渲染这块(`IS_DEV` 判断),设计稿如果画出来,要清楚标注这是开发态,
   不是所有用户都会看到的内容。
5. **深浅色单一 JSX**,同前两份简报的红线。
6. **`ScanLoginCard` 必须能被 `LeagueGateCard` 直接嵌入**——不要设计成
   占满整个视口高度或依赖 `/login` 页面级的其他元素(比如页面标题)才能
   成立的样子;它要能在一个联赛数据页中间"弹出"一张卡的场景下也站得住。

## 6. 完整字段/文案清单

| 内容 | 来源 | 说明 |
|---|---|---|
| 环境标题/提示 | `ENV_TITLE`/`ENV_HINT`(前端常量) | 三档,见 §3 |
| `qr_url` | `POST /auth/wechat/device` | 二维码真实内容 |
| `expires_at` | 同上 | 真实过期时间,驱动倒计时 |
| 已登录提示 | `GET /me` | `me.user.display_name` 可能为空,退回 `me.user.id` |
| 微信登录开关 | `GET /auth/methods` | `wechat_enabled` 三态:`null`(未知,按可用渲染)/`false`(明确关闭)/`true` |
| 管理员密码登录 | `POST /auth/password/login` | 折叠区,仅站长自己用,不是普通用户入口 |
