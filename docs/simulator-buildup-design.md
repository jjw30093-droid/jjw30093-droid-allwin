# 模拟器动画第二层:进攻过程(设计稿,未实现)

> 2026-09-30。站长要求"先交设计,不实现"。本文只描述方案与工作量,代码里没有任何相关实现。

## 1. 目标

每次射门前,球从中场出发,经过 2–3 次传递到达射门点;反击、角球、任意球、运动战的路径各不相同。
**只画球的路径,外加传球人和射门人两个号码点**,不画 22 名球员。

## 2. 数据边界(先说清楚能做到什么)

- 库里**没有传球 / 触球序列数据**:core 只有 `fact_shotmap`(射门点、方式、结果、越线点)、
  `fact_match_events`(进球、红黄牌等)、`fact_match_momentum`(每分钟势头值)、阵容与球员逐场统计。
- 因此进攻路径**只能按渠道规则合成**,不是真实比赛回放。终点(射门点)用第一层已经抽到的真实射门;
  起点和中间传递点是示意。页面与录屏画面都要写明"进攻过程为示意",不能让人误以为是真实传球线路。
- 可以用到的真实信息:射门点与渠道(`SimEvent.sd`、`channel`)、双方首发与号码(结果快照里有)、
  球员场均 xA(`PlayerParams.xa90`,用来决定"谁更可能是传球人")。

## 3. 路径规则(进攻方坐标:x 0–105 朝对方球门,y 0–68,y < 34 = 右路)

| 渠道 | 起点 | 传递 | 最后一传 → 射门点 |
|---|---|---|---|
| 运动战 `open` | 中圈附近(x 50–58,y 随机) | 2–3 次:先横向或斜向转移,再纵向推进到 x 70–85 | 射门点在禁区中路 → 从两翼(y<18 或 y>50)传中或倒三角;射门点在禁区外 → 从正前方短传 |
| 反击 `counter` | 本方半场(x 25–45)抢断点 | 1–2 次长距离纵向传递(每次 ≥ 20 米),线路更直 | 直塞到射门点身后 3–6 米 |
| 定位球 `setpiece`,射门点在禁区内 | 角旗区(x 105,y 0 或 68,按射门点所在一侧选近角)或禁区外任意球点(x 75–88) | 1 次:弧线传中 | 落点 = 射门点(头球时画成高球:球变大再变小) |
| 定位球 `setpiece`,射门点在禁区外 | 无 | 无 | 直接任意球:射门点就是罚球点,只画一脚 |
| 点球 `penalty` | 无 | 无 | 只画点球(第一层已实现) |
| 门将失误 `gk_error` | 对方门将脚下(x 103,y 34) | 1 次:短传被断 | 断球点 → 射门点 |
| 乌龙 `owngoal` | 进攻方边路传中点 | 1 次:传中 | 防守球员碰球入网(第一层已实现) |

每一段传递点在上表范围里按事件的独立随机数流取值:`eventRng(模拟编号, 事件序号, 3)`,
与第一层的射门细节(用途 0)、解说句式(用途 1)互不影响,不碰模拟本身的随机数流。
传递点做两条约束:不出界(y 2–66)、相邻两点距离 8–40 米(反击的纵向传递 20–45 米)。

## 4. 传球人与射门人

- 射门人:事件里已有(`playerId`、号码取自快照阵容)。
- 传球人:从进攻方场上 11 人中(不含射门人、门将;定位球允许门将以外所有人)按 `xa90` 加权抽取;
  定位球优先该队 `xa90` 最高的中场 / 边锋(近似"主罚人",库里没有真实主罚人数据,需如实说明)。
- 传球人要写进结果快照(每脚射门多一个 `ap` 字段),否则参数更新后分享链接里的传球人会变。
  实测(2026-09-30,第一层上线后,五个联赛各 6 次模拟共 30 条):整条分享链接 3,045–3,848 字符,中位 3,413;
  第一层的射门细节让结果部分多了约 420–510 字符。离 4,000 字符的上限已不宽裕——加 `ap` 前要先压缩
  (例如射门细节终点取 1 位小数、`ap` 只存阵容里的位置序号 0–10),实现时复测最长的情况。
- 画面:射门人、传球人各一个带号码的圆点(本队颜色),传球人在最后一传发出点、射门人在射门点;不画其它球员。

## 5. 时间线与节奏

- 每脚射门前加一段进攻过程:2–3 段传递,每段 250–400ms,反击更快(每段 200ms)。
- 如果每脚都画,1 倍速一场会从约 45 秒拉长到约 75 秒,太长。建议**只给进球与 xG ≥ 0.15 的射门画进攻过程**
  (约占射门的三成),其余射门维持第一层的直接飞行。这样 1 倍速约 55 秒、2 倍速约 28 秒。
- 同一分钟多脚射门时,第二脚起不画进攻过程(避免画面叠在一起)。
- 录屏模式同样适用;竖版球场只是坐标换算不同(第一层的 `toStage` 已支持)。

## 6. 实现要点

- 新增纯函数 `features/simulator/buildup.ts`:`buildupPath(event, index, seed, lineup) → { points, passerId }`,
  不依赖 React,可测试:路径点都在界内、相邻距离在范围内、终点 = 射门点、同一编号结果不变、各渠道起点区域正确。
- `playback.ts`:射门的"起脚时刻"前插入进攻过程时长;`eventStart` 语义不变(= 起脚)。
- `pitchCanvas.ts`:按时间画球沿折线移动、两个号码点;第一层的飞行与收尾效果不变。
- 解说:有进攻过程的射门在句首加传球人("厄德高送出直塞,萨卡……"),模板测试同样检查禁用词。
