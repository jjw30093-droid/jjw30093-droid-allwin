## 2026-11-10 第三轮：修复官方 xA 漏读及报告覆盖

更正第二轮结论：CC 有官方 xA。实际来源为当前 `op_match.raw_sha256` 对应原始归档的 `feeds.xgmap.liveData.lineUp[].player[].stat[]`，包括 `expectedAssists`、`expectedAssistsOpenplay`、`expectedAssistsSetplay`。旧入库仅处理 matchstats 与 matchstats_detailed，报告又只读 detailed 主视图，因此漏掉了 xgmap 球员统计，不能将此表述为供应商缺少数据。

新入库保留 xgmap 统计；历史报告只读已入库版本对应归档，校验解压内容 SHA256、比赛及球员/球队身份，再提取官方总 xA。总值不与运动战/定位球分项重复相加。每位球员保存逐场来源和覆盖，整场 xA 不拆到区域、比分状态或选区，也不除以选区分钟生成 xA/90。源数据库无 schema 或数据变更，不需要复制整库。

本轮补齐的已存数据到报告的链路：

| 维度 | 报告入口及口径 |
|---|---|
| 逐场近期表现、5/10场背景 | 同截止时间与筛选的 xG/xGA 趋势、对手和主客场；不足10场显示实际场数 |
| 出球起点与传球结构 | 回合数、射门回合率和每回合已记录 xG |
| 进攻方式效率 | 展示未形成射门的回合分母，不只列成功机会 |
| 推导带球 | 次数、推进次数与事件入口；明确相邻动作代理 |
| 攻防转换 | 夺回后15秒内射门及价值、双方事件证据 |
| 双人组合 | 报告内选择两人生成独立版本；赛前和赛后均支持四组及小样本提示 |
| 换人、阵型、比分和人数区间 | 各区间分钟、射门/xG及在场名单，累计时间含补时，不作换人因果结论 |
| 15分钟过程 | 射门/xG、传球成功率、≥30米传球代理与可配对对抗结果 |
| 对抗双方 | 去重后的球员×对手关系及事件；犯规不冒充争顶胜负 |
| 比赛记事 | 实际进球、牌和换人节点，可回到事件 |

## 工作流与数据归属

1. 私有 CC 服务 `/v1/report-workflow/candidates` 列出未来 72 小时英超和最近 14 天已完赛英超；即使同时存在未来赛程也不漏赛后。
2. 网站 worker 每 60 秒检查已入库来源指纹、历史样本版本、模型版本、MA27/MA30/MA32 存档版本及 VIP 名单／伤停；复用 job_runs，单写者事务领取，最多三次尝试、失联任务租约恢复。没有供应商采集调用。
3. 私有 `/v1/report-workflow/postmatch/{uuid}` 只读 CC 数据。赛前复用原接口，赛后包含阶段 1–4、所有人数状态、点球；点球大战分开。
4. 网站 POST `/api/v1/studio/reports/generate` 入队。`content_drafts`、`research_draft_links/events`、`analyst_report_links` 保存不可变证据、前后版本与对应赛前报告。
5. 人工文字、录像观察、撤回原因单独存 overrides；不能改指标和事件。编辑后回到待审核；审核与导出带 expected_revision，防止过期版本操作。
6. 已审核报告不被新数据覆盖；新版本独立待审。赛后核验标明对应赛前版本与审核版本，历史重建不冒充当时已保存。
7. PDF 与 JSON 从相同固定快照＋指定编辑版本导出，复用 export_jobs；不自动发布。缺失可嵌入中文字体时明确报错，不交付乱码 PDF。

目前文字初稿采用结构化证据模板，可人工修订。没有让语言模型自行计算、补数字或杜撰因果。
